# Upper-limb soft-tissue constraint model

MJ Anatomy should not treat joints as unconstrained animation pivots. Motion is generated by the bone hierarchy, then limited by anatomical joint geometry and passive soft tissues.

## Constraint representation

Each ligament or tendon path will be represented by named attachment landmarks on parent bones, plus a path model where wrapping is needed.

```ts
interface Attachment { boneId:string; local:[number,number,number] }
interface LigamentConstraint {
  id:string;
  origin:Attachment;
  insertion:Attachment;
  slackLength:number;
  toeStrain:number;
  maxStrain:number;
  role:string;
}
```

At runtime, attachment landmarks are transformed with their bones. Ligament length is measured in world space. Below slack length it does not impose a hard stop; through the toe region restraint rises progressively; beyond the guarded maximum the requested pose is rejected/clamped. This is an educational kinematic constraint model, not a finite-element tissue simulation.

## Shoulder

The glenohumeral capsule/ligaments are position dependent, so a single universal rotation limit is not anatomically adequate. The model should eventually include SGHL, MGHL, the inferior glenohumeral ligament complex and coracohumeral ligament as separate paths. Scapular and clavicular motion must be solved before high-elevation humeral motion is accepted.

## Elbow and forearm

The elbow is three articulations: ulnohumeral, radiocapitellar and proximal radioulnar. Medial/ulnar and lateral collateral complexes constrain coronal/rotatory instability. The annular ligament must retain the radial head during forearm rotation. Radius and ulna are additionally coupled by the interosseous membrane, and distal radioulnar stability must be treated as part of the whole forearm.

Pronation/supination therefore cannot be implemented as a radius spinning about its own bounding-box centre. The proximal radial head, radial shaft, distal radius and hand need a common forearm kinematic solution relative to the ulna.

## Implementation order

1. Replace guessed AABB pivots with explicit anatomical attachment/joint landmarks.
2. Add ligament origin/insertion landmark data.
3. Add world-space length and strain evaluation.
4. Add progressive constraint solving instead of hard angle-only clipping.
5. Add tendon paths and muscle origin/insertion data.
6. Muscle Action commands request shortening/torque; the constraint solver determines the allowed resulting pose.
