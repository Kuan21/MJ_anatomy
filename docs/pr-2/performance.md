# 拖動滑桿的主執行緒耗時（PR 2）

量測方式：無頭 Chromium（軟體 WebGL，沒有實體 GPU），載入完成並等到背景工作結束後，每幀程式化送出一次滑桿 input 事件，共 60 幀，以 Chrome DevTools `Performance.getMetrics` 的 `ScriptDuration` 取每幀 JavaScript 時間（閒置時約 0.1–0.5 ms）。畫面繪製在 GPU 行程內，這個環境量不到真實 GPU 的 fps，所以只用「每幀 JavaScript 時間」作指標；兩個版本的 requestAnimationFrame 間隔同為約 17 ms。

| 情境 | 改動前（每幀 JS） | 改動後（每幀 JS） |
| --- | --- | --- |
| 骨骼＋肌肉 | 8.1 ms | 7.2 ms |
| 全部系統（骨骼、肌肉、動脈、靜脈、神經、體表、結締） | 9.0 ms | 5.7 ms |

改動後的項目已包含新增的膠囊碰撞（每幀約 0.2–0.7 ms）。

做了什麼：
1. 滑桿自己保存拖動中的數值，每次拖動只重繪這個小元件；整頁（Home）狀態改為每個動畫幀只更新一次，並一併處理關節限制與碰撞（原本每次輸入各更新兩次）。
2. 「目前可見構造數」改用 useMemo，拖動姿勢時不再每幀逐一掃過 2,300 個構造。
3. 上肢運動求解器把與姿勢無關的資料（骨骼框、關節中心、肋骨殼、骨骼綁定）改為每個圖譜只計算一次：一次手臂求解由 2.1 ms 降到 0.2–0.7 ms。
